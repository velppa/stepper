#+title: Stepper

Local runner for state machines described in [[https://states-language.net/][Amazon States Language]] —
personal AWS Step Functions.  Deterministic workflows without the
cloud.

* Design
- JSONata only :: =QueryLanguage: JSONata=; JSONPath mode is not
  supported.  Data flow uses =Arguments=, =Output=, =Assign= and
  =Condition= with the reserved =$states= variable.  Engine:
  [[https://github.com/dashjoin/jsonata-java][dashjoin/jsonata-java]].
- Local :: data lives in a SQLite database
  (=~/.local/share/stepper/stepper.db=), no auth.
- Tables :: singular — =state_machine=, =state_machine_version=,
  =execution=, =execution_event=, =schedule=, =firing=.
- Versions :: editing a definition appends a =state_machine_version=;
  the highest version is the current one.  An execution starts from the
  current version and stays pinned to it, so editing never changes what
  a past execution ran.
- Task resources :: named by SRN (Stepper Resource Name):
  - =srn:local:shell:::shell:runCommand= — {command, cwd, env,
    timeout_seconds} via =/bin/sh -c=
  - =srn:local:shell:::shell:runFile= — {file, args, cwd, env,
    timeout_seconds} runs a script file via bash
- States :: Task, Choice, Wait, Succeed, Fail, Pass, Parallel, Map.
- Validation :: a definition is checked before it is stored — JSON,
  ASL shape, reachable state names and compilable JSONata expressions.
  The UI, the API and the CLI all report what is wrong and store
  nothing.
- Scheduler :: cron (=*/5 * * * *=) or =rate(N minutes)= expressions
  start machines in =serve= mode.  A schedule carries an event
  template — a JSON document whose ={% %}= expressions are evaluated at
  fire time and sent as the machine's input, with =$input.time= as the
  firing time.  Executions are not bound to schedules — the =firing=
  table keeps the history of firings with the started execution's SRN.
- Retention :: the newest 2000 executions of each state machine are
  kept, older ones and their events are pruned as executions finish.
- UI :: HTMX served by http-kit.
- API :: AWS Step Functions wire protocol on the same port, so
  =aws stepfunctions --endpoint-url http://localhost:8321= works:
  Create/Update/List/Describe StateMachine, ListStateMachineVersions,
  Start/Describe/List Execution, GetExecutionHistory.  Schedules are
  Stepper's own concept and ride the same protocol:
  List/Create/Update/DeleteSchedule.

* Usage
#+begin_src sh
clojure -M:run create <name> <definition.json>
clojure -M:run update <name> <definition.json>   # appends a version
clojure -M:run versions <name>
clojure -M:run start <name> '<input-json>' [execution-name]
clojure -M:run list
clojure -M:run schedule <name> 'rate(30 minutes)' '<input-json>'
clojure -M:run schedules
clojure -M:run serve [port]     # UI + API on http://localhost:8321

aws stepfunctions list-state-machines --endpoint-url http://localhost:8321
#+end_src
